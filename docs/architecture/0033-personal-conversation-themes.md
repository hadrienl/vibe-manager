# 0033 — Personal conversation themes, made with an agent

- Status: accepted
- Date: 2026-09-29
- Issue: [#118](https://github.com/hadrienl/vibe-manager/issues/118)
- Amends: [0025](0025-conversation-view.md), which left personal themes to a later issue

## Context

ADR 0025 shipped six themes and held every pair a reader must read to WCAG contrasts. #118 lets
the user make a theme of their own by describing it to one of the agents already on the Mac,
refine it version after version while seeing it applied, keep it, export it and delete it. That
needs a file format, a place to keep themes, a way to ask an agent for one without letting what it
answers do anything but colour the view, and a trial that can always be dropped.

Four principles decide most of what follows:

1. **A personal theme is a theme like the others.** Resolved, drawn, chosen and held to the same
   contrasts as the built-in ones; no view of the conversation knows where its theme comes from.
2. **The trial never touches the settings.** A version generated is shown, never written: only
   saving changes `ConversationAppearance`.
3. **What the agent answers is data.** Decoded strictly, then checked; nothing in it is run,
   interpreted, or used as a path.
4. **One definition of the format.** The schema in the repository documents the file, is what the
   agent is held to, and a test keeps it equal to the code.

## Decisions

### The theme's data moves to `VibeApplication`

`ThemeColor`, the fields of `ConversationTheme`, the built-in themes, `resolve` and the rules of
legibility leave `VibeConversationUI` for `VibeApplication`, so that a theme is checked and
generated without a view. What SwiftUI and AppKit need — colours, fonts, localized names, the
environment — stays in `VibeConversationUI` as extensions.

`ColorRole` names the 27 colours; `legibilityRules` names each pair by its roles, with its ratio.
The pairs of 0025's test, the checks of a personal theme and the contrasts the agent is told all
derive from those rules.

### The file, format 2

```json
{ "format": 2, "name": "Forêt de nuit", "isDark": true, "fontStyle": "system",
  "colors": { "background": "#14201A", …, "bubbleBorder": null },
  "fonts": { "message": "Inter", "code": null },
  "layout": { "blockSpacing": 18, "paragraphSpacing": 10, "topPadding": 28, "lineHeight": 1.25,
              "contentWidth": 820, "sideMargin": 32, "bubbleRadius": 16, "blockRadius": 10 } }
```

Format 1 — the colours alone, before a theme could ask for fonts and a layout — is still read:
its theme has the system's families and the layout of the built-in ones.

- **The schema** is `docs/schemas/conversation-theme-2.schema.json`, generated by
  `ConversationThemeSchema.document`; a test fails when they differ, and
  `VIBE_WRITE_THEME_SCHEMA=1` writes it again. It is built in code rather than read from a
  resource so that the roles, their purposes and the rules cannot drift apart. The agent is held to
  a stricter variant of it (`forAgent`): every property required, no other allowed, and none of the
  keywords the strict mode of Codex refuses — lengths, bounds, patterns of names, `$schema`,
  `default`; the ranges are said in the descriptions and checked on arrival. The
  mode asked for is said in the description of `isDark` rather than pinned, and checked on
  arrival.
- **No identifier in the file**: the file's name gives it, `personal-<name without .json>`. Two
  files cannot claim one theme, and an import will only have to give a new name.
- **Read strictly** (`ConversationThemeFile`): an unknown or missing key, a `format` other than 1 or 2,
  a colour that is not `#RRGGBB`, a boolean that is a number, a name empty, longer than 40
  characters or holding a control, a line break or a character that reorders text — each is a
  `ThemeFileProblem` with English details precise enough to be sent back to the agent as they are.
  So is a number of the layout outside its range, and a family name that is not letters, digits,
  spaces and hyphens: nothing else can reach a URL or a folder built from it.
- **Held to the contrasts everywhere**: a generated theme, and a file of the library at every load.
  A file edited by hand until a pair no longer reads is left out like an unreadable one: every
  theme shown can be read.

### Fonts and layout

A theme may ask for a family for the messages and one for the code. The user's own choice of font
in the settings still wins; a family that cannot be drawn gives way to the system's family of the
theme's `fontStyle`.

- **Installed or from Google Fonts.** A family every Mac has is used as it is. Any other is looked
  up on Google Fonts (`GoogleThemeFonts`): the style sheet of `fonts.googleapis.com` lists its
  regular, bold and italic faces — TrueType, since the request names no browser —, the files are
  fetched from `fonts.gstatic.com` only, each checked to be a font CoreText reads, kept in
  `Themes/Fonts/<Family>/` and activated for the application alone: nothing is installed for the
  rest of the system. The fonts kept are activated again when the library is read, at launch.
- **A family that exists nowhere is the agent's mistake**: its answer is sent back, like an
  illegible one, with "neither a font installed on every Mac nor a family of Google Fonts".
  Google out of reach is not: the theme is kept, and drawn with its system family meanwhile.
- **An export carries the families it fetched**, under `fonts/<Family>/`: Google Fonts families
  are under the SIL Open Font License, which allows it, and whoever imports the theme will not
  need Google.
- `NSFontManager` keeps the list of families it read first: whether a family is there is asked of
  CoreText, which sees the ones activated since.

The layout gives, in points, the spaces between blocks and between paragraphs, the space above the
first message, the height of a line, the widest the column gets, the side margins, and the corners
of the bubbles and of the blocks — each within a range where the view still reads and lays out.
They are the values of the Comfortable density; Compact tightens the spaces as it always did, so
the setting keeps its meaning with every theme. The built-in themes carry the values the view used
before, and draw exactly as they did.

### The library

```
Themes/          0700, beside Avatars/ in the data folder
  <uuid>.json    0600, the file of the theme personal-<uuid>
```

- Written in a staging file, then renamed over: the file is the old one or the new one.
- **No index and no lock.** Nothing but the themes is kept — the order is the order the files were
  made in — and two instances cannot write the same identifier. The tab reads the library again
  each time it appears.
- **A file that cannot be read is left out, left where it is, and said**: under the grid, with its
  name and why, and "Show in Finder"; in the diagnostics, `theme.unreadable` with the code of the
  problem only. Nothing is ever deleted but by the user.
- **A name already taken** — by a theme of the library or a built-in one, in English or as the user
  reads it, whatever the case and the accents — gets the first free number: "Forêt 2".
- **Deleting a theme in use** gives each mode that used it its default theme. A theme gone behind
  the application's back — deleted by hand, or no longer readable — gives the mode's default theme
  too, without the setting being rewritten: the file back, the theme is back.
- **Export** writes a `.zip` of `theme.json` and `preview.png`, the card of the theme drawn at twice
  its size. Import is a later issue; the format exported is the file itself.

### Asking an agent

`ConversationThemeGenerating` is a port; `AgentThemeGenerators` offers the agents that make themes
**and are available now** — the panel only offers what can work. Claude Code and Codex make themes
with `CommandLineThemeGenerator`, on the model of the summaries of the journal (#36): one pass of
the CLI with the user's own account, outside any session, from an empty temporary folder, without
MCP servers, hooks, plugins, web search, memory or transcript, the answer held to the schema.
Claude Code runs without any tool. Codex cannot be run without its shell: as for the summaries,
it keeps it in a read-only sandbox without the network, which the description — written by the
user alone — could at most make read a file, never write one nor send it anywhere. Claude Code runs `sonnet` — 27 colours that go together and
contrasts computed rather than guessed —, Codex the account's model; 120 seconds at most.

`ThemeInstructions` says what each colour is for, every contrast with its ratio and the formula,
the mode, and the language of the name. From the second version on, the current version and what
was asked before are given, to be changed rather than started again. The user's description comes
last, between delimiters it cannot close, as a description to interpret and never instructions.

`GenerateConversationTheme` checks the answer, and when it cannot be used sends it back **once**
with what is wrong with it. A failure of the agent itself — signed out, too old, too slow — is not
tried again: it would only double the wait.

The diagnostics hear `theme.generation`: how it ended, how many attempts, how long, and how many
characters the description had — never the description, the name nor the answer.

### The trial

`ConversationThemesModel` belongs to `ConversationWorkspace`, which reads the library at launch: a
conversation drawn with a personal theme needs it before the settings are ever opened. Its `trial` is the last version while
the panel is unfolded; `displayed(_:isDark:increasedContrast:)` is what both the preview of the
settings and every conversation of the main window draw with: the trial, with its own accent —
what is being made —, or the theme the settings resolve to. Folding the panel, choosing a card,
leaving the tab or closing the window empties the versions and stops a generation under way; the
theme in force is back without anything to restore, and a crash or a quit in the middle leaves
nothing to repair.

Saving gives the theme to the mode it was made for — the dark slot when the settings follow the
system and the theme is dark, the single slot otherwise, as a card does, and then it is said
"applied" rather than tied to a mode — and, when the user had
chosen an accent of their own, gives the theme its accent back unless the user unticks "Use the
theme's accent".

The mode is chosen before the first version and fixed afterwards: another mode is another theme,
and Start Over is the way to it.

### Accessibility

The card is a button whose value is Folded or Unfolded; the description takes the keyboard when the
panel unfolds; each version is one element that reads its number, its request and its agent. A
personal theme's card offers Export and Delete as accessibility actions, and Delete with the
keyboard, since a context menu is not reached without a pointer. The model announces, each once:
a generation that starts, a second attempt, a version on trial, a failure and why, a cancellation,
a return to a version, a theme dropped, saved — with its final name and its mode — or deleted.

## Consequences

- A personal theme is not checked against the six preset accents: requiring it would forbid most
  mid-tone backgrounds. The test "every accent on every theme" stays with the built-in ones.
- Folding the panel drops the versions without asking, as #118 asks, although a generation costs
  quota.
- An earlier version knows nothing of `Themes/`: a personal theme in use there resolves to the
  mode's default theme.
- Checked by hand only: the trial seen in the main window behind the settings, VoiceOver and the
  keyboard alone on the panel, a real export opened in the Finder. A generation by the real agents
  is a test that runs on demand (`VIBE_THEME_INTEGRATION=1`).
