Terminaux annexes et vue web

Chaque session a son propre tiroir de terminaux pour un serveur, un journal ou une commande git, et sa propre vue web, que vous partagez avec l’agent.

Terminaux annexes

Présentation › Afficher les terminaux (⌘J), ou le bouton terminal de la barre d’état, ouvre un tiroir sous la session. Présentation › Nouveau terminal (⌘T) ajoute un onglet. Chaque onglet est un shell de connexion lancé dans le dossier de la session, intitulé d’après la commande qu’il exécute ou le dossier où il se trouve.

Le tiroir des terminaux annexes, sous la session.
  • Masquer le tiroir n’arrête rien. Un terminal masqué qui écrit ou se termine est signalé sur le bouton de la barre d’état.
  • Double-cliquez sur un onglet pour le renommer ; son menu contextuel le déplace vers la gauche ou la droite, ou le ferme (⌘W quand il a le clavier). ⌃⇥ et ⌃⇧⇥ passent d’un onglet à l’autre.
  • Un shell terminé propose de redémarrer ou de fermer.
  • Jusqu’à huit terminaux par session.

Les terminaux annexes appartiennent à leur session : ils s’arrêtent quand elle se ferme, et reviennent quand elle se rouvre ou quand l’app est relancée — mêmes onglets, même ordre, même dossier, ce que chacun affichait — sous forme de nouveaux shells sous une ligne datée. Rien n’est réexécuté. Si vous quittez avec Laisser tourner, ils continuent de tourner avec leur agent.

Leur historique est la seule sortie de terminal écrite sur le disque ; Réglages › Terminaux permet de le désactiver et de l’effacer.

La vue web

Présentation › Afficher la vue web (⌥⌘B), ou le globe de la barre d’outils, ouvre un navigateur à côté de la session, avec ses propres onglets. Changer de session change d’onglets ; rien n’est rechargé.

L’agent a ouvert son aperçu local dans la vue web de la session.
  • Le menu Web propose les commandes habituelles : Ouvrir l’adresse… (⌘L), Recharger la page (⌘R), Précédent et Suivant (⌘[ ⌘]), Ouvrir la page dans le navigateur.
  • Le champ d’adresse accepte aussi un ticket : tapez #142.
  • Le ticket de la session est son premier onglet, épinglé. C’est celui que vous avez donné à la session, ou celui que nomme sa branche (feat/142-… sur GitHub ou GitLab). Le menu Plus permet de le définir, de le changer ou de le retirer.
  • Un ⌘-clic sur un lien dans un terminal l’ouvre dans la vue web ou dans votre navigateur — Réglages › Vue web en décide, et un ⌥⌘-clic fait l’inverse.
  • Toutes les sessions partagent un même jeu de cookies, distinct de celui de Safari : connectez-vous une fois à GitHub ou GitLab, et tous les onglets de tickets sont connectés.

Ce que l’agent peut en faire

Chaque agent est lancé avec un serveur d’outils, vibe-browser, qui lui donne la vue web de la session : lister, ouvrir, recharger et fermer des onglets, lire le texte ou la structure d’une page, faire une capture d’écran, lire la console, cliquer, remplir des champs et exécuter du JavaScript. L’agent ne voit que les onglets de sa propre session. Dans les terminaux, la commande vibe browser fait de même depuis un script, et un open https://… lancé par l’agent affiche la page ici.

Quand l’agent veut agir sur un autre site, un bandeau dans la vue web vous demande : Refuser, Autoriser une fois ou Toujours autoriser pour ce site. L’agent attend deux minutes au plus ; la ligne de la session affiche une main pendant ce temps. L’onglet ouvert par l’agent porte une marque, l’élément sur lequel il clique est entouré, et le journal Actions de l’agent liste ce qu’il a fait.

La lecture est libre partout, y compris sur les pages où vous êtes connecté : un agent peut lire un ticket privé. Désactivez Donner la vue web aux agents dans Réglages › Vue web si vous ne le souhaitez pas.
