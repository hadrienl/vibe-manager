Dépannage et confidentialité

Où se trouvent vos données, comment vous sortir de ce qui peut mal tourner, et comment signaler un problème.

Signaler un problème

Aide › Signaler un problème… ouvre un nouveau ticket sur GitHub. Joignez-y un fichier de diagnostics : c’est ce qui aide le plus.

Exporter les diagnostics

Aide › Exporter les diagnostics… rassemble le journal local de l’app et montre le fichier en entier avant que vous l’enregistriez. Le journal se compose de types d’événements, sans place pour du texte libre : il ne contient aucun prompt, aucune note, aucun nom de session ou de dossier, aucun contenu de terminal. Il est conservé dans ~/Library/Logs/Vibe Manager deux semaines au plus, et rien n’est jamais envoyé.

Problèmes courants

Un agent est introuvable
Le formulaire de nouvelle session et les Réglages en donnent la raison : non installé, non exécutable, trop ancien ou non connecté. Installez-le ou connectez-vous depuis un terminal (claude auth login, codex login), puis cliquez sur Relancer la détection. Voir Comment les agents sont trouvés.
« Sessions indisponibles », ou le fichier des sessions est dit endommagé
Restaurer la sauvegarde rétablit la version précédente ; le fichier endommagé est conservé à côté, jamais supprimé. Sans sauvegarde, quittez, déplacez sessions.json ailleurs et relancez l’app.
Les agents laissés en cours ne peuvent pas être rattachés
Une autre copie de l’app les détient, ou l’hôte des terminaux n’a pas répondu à temps : cliquez sur Réessayer dans le bandeau. En dernier recours, pkill -f -- 'Vibe Manager --terminal-host' arrête l’hôte et les agents qu’il gardait ; leurs conversations sont reprises au lancement suivant.
L’Accès complet au disque est accordé, et les agents sont toujours sollicités
Les agents héritent de l’accès du processus qui les a lancés. Dans Réglages › Confidentialité, choisissez Redémarrer à la fin des agents ou Redémarrer maintenant….
La conversation reste vide
La conversation est lue dans le transcript qu’écrit l’agent ; un message apparaît dès que la CLI l’a écrit. Si un message que vous avez envoyé ne s’affiche pas dans les dix secondes, la vue le signale et propose le terminal, qui fait toujours foi.
L’activité de la session ne s’affiche pas (en cours, en attente…)
Activez l’activité de l’agent dans Réglages › Agents et approuvez ses hooks.
Aucune mise à jour n’est proposée
Vibe Manager › Rechercher les mises à jour… explique pourquoi quand cette copie ne peut pas se mettre à jour elle-même. Les versions candidates ne sont proposées que sur le canal Instable. Vous pouvez toujours télécharger la dernière image disque depuis GitHub Releases et glisser l’app par-dessus l’ancienne.

D’autres cas sont traités dans Aide › Dépannage, qui ouvre docs/operations.md.

Ce qui reste sur votre Mac

  • Pas de compte, pas de télémétrie, rien d’envoyé. Les seules requêtes réseau que l’app fait d’elle-même sont la recherche de mises à jour et les pages que vous, ou vos agents, ouvrez dans la vue web.
  • Aucun identifiant n’est lu. Les agents utilisent leur propre connexion ; Vibe Manager ne voit jamais de clé d’API.
  • Les conversations sont lues, pas copiées. La vue conversation lit les transcripts des agents en mémoire ; le suivi de l’utilisation ne lit que leurs compteurs.
  • Les résumés, les thèmes et les avatars sont générés par vos agents, avec votre compte, seulement quand vous les activez ou les demandez.
  • Chaque fichier de l’app n’est lisible que par vous.

Limites connues

  • Redémarrer le Mac ou fermer la session utilisateur arrête les agents ; Laisser tourner ne survit qu’à l’app.
  • Chaque terminal garde ses 5 000 dernières lignes.
  • Après une relance, un terminal annexe revient sous forme de nouveau shell : ce qui y tournait n’est pas réexécuté.
  • Un fichier des sessions écrit par une version plus récente est refusé par une version plus ancienne : aucun retour en arrière n’est possible.
  • L’app n’est pas sandboxée : un agent doit pouvoir exécuter des outils et lire les dossiers qu’on lui confie.

Désinstaller

Quittez l’app — choisissez Tout arrêter si elle le demande —, puis, dans un terminal :

rm -rf "/Applications/Vibe Manager.app" \
  ~/Library/Application\ Support/com.hadrienl.VibeManager \
  ~/Library/Logs/Vibe\ Manager \
  "$TMPDIR/vibe-manager"
defaults delete eu.hadrien.VibeManager
tccutil reset All eu.hadrien.VibeManager
