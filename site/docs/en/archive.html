Automatic archive

Describe in one sentence which sessions to archive and when: an agent turns it into a rule, which you test before turning it on. Each archiving forms a batch, and the reports tell what the sessions put away contained.

Rules in one sentence, and what they must never touch.

Write a rule

Settings › Automatic Archive › New Rule… asks for a sentence: “Every Friday at 6 pm, archive the sessions done for more than two days, except those of billing-api.” An agent translates it into a strict language; the app reads it back to you in plain words, with its next runs. Refine corrects it with another sentence.

Only Done sessions are concerned. A session where something is running is always skipped, a session you took out of the archive is not sent back there, and a fact the app does not know archives nothing.

  • Test opens the bench: it shows the sessions the rule would archive now, without touching anything.
  • Try First puts it on trial: it runs dry and notes what it would have archived.
  • Turn On puts it in service; Pause suspends it.

The protections, described the same way, name the sessions no rule must ever archive.

Batches

Each run of a rule forms a batch: the sessions archived, and those skipped with their reason. A selection archived at once forms its own batch, and sessions archived one by one form one batch a day. Archiving by a rule is not undone with ⌘Z: unarchive from the archive.

In a rule's sheet, Summarize each batch with an agent has an agent write what was done in the batch's sessions. For a selection, the archive confirmation offers Archive and Summarize, which then opens the batch's report.

Reports

What was put away, batch by batch.

Window › Archive Reports, or Show Reports under the archive list, reads them by batch or by period — today, yesterday, 7 days, this month, or chosen dates —, by project, with the totals. An agent can summarize them, and a report exports to Markdown.
