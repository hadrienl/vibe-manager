Answer your agents

An agent in a background session that stops for a permission or a question does not wait for you to open its session: its request comes to you.

What an agent can ask

  • A permission: run a shell command, edit a file, fetch an address. Answer Allow, Always (when the agent offers to remember it) or Refuse.
  • A question, with options to pick or Another answer… to type your own; Send Answers when there are several.
  • A plan to approve (Claude Code): Approve, Accepting Edits, Approve, Reviewing Each Edit, or Reject.

In the session on screen, the request is shown in the conversation, in place of the composer. Elsewhere, it goes to the palette.

Refuse also ends the agent's turn: it then waits for your next message. That is how the CLIs work: refusing presses Escape.

The Pending Requests palette

The palette sits at the foot of the sidebar and lists the requests of every other session, oldest first, whatever their column. Each card says which session asks, with which agent and in which folder, and shows the command or question in full; Show All unfolds a long one.

Two sessions waiting for approval, answered without leaving the session on screen.
  • Click Allow or Refuse: the answer is typed into that session's terminal, exactly as you would have, and your own session keeps the keyboard.
  • The arrow button, or ⌘Return, opens the request's session.
  • ⌥⌘P gives the palette the keyboard: ↑ ↓ between requests, Tab then Space on an answer, Esc to go back.
  • The header folds the palette into a count.

A request whose details were cut, or that cannot be told apart from another, can only be answered in its terminal: the card says so and offers Answer in the Terminal.

When Vibe Manager is in the background

You do not have to keep Vibe Manager in front to know an agent waits. Choose, in Settings › Requests › Alerts:

Notifications
A system notification for each request, showing either the kind of request or the command itself. A permission can be allowed or refused right from the notification. The Dock icon counts the pending requests.
The floating panel
An avatar, in a bubble above every other app and on every Space, that shows the requests one by one and lets you answer them where you are. It never takes the keyboard on its own: press ⌃⌥⌘P to lend it the keyboard (← → between requests, ⌘Return to open the session, Esc to give the keyboard back). Drag it anywhere; its place is remembered per screen. While it is on, no notification is posted, since the bubble already says it.

The avatar can be the default one, one you import, or one an agent draws from your description: see Themes and avatars.
