Troubleshooting and privacy

Where your data lives, how to recover from what can go wrong, and how to report a problem.

Report a problem

Help › Report an Issue… opens a new issue on GitHub. Attach a diagnostics file: it is what helps most.

Export Diagnostics

Help › Export Diagnostics… gathers the app's local log and shows the whole file before you save it. The log is made of event types with no room for free text: it holds no prompt, note, session name, folder name or terminal content. It is kept in ~/Library/Logs/Vibe Manager for two weeks at most, and nothing is ever sent.

Common problems

An agent is not found
The New Session form and Settings say why: not installed, not executable, too old, or not signed in. Install or sign in from a terminal (claude auth login, codex login), then click Detect again. See How agents are found.
“Sessions unavailable”, or the store is said to be damaged
Restore Backup puts back the previous version; the damaged file is kept beside it, never deleted. Without a backup, quit, move sessions.json aside and relaunch.
Agents kept running cannot be reattached
Another copy of the app holds them, or the terminal host did not answer in time: click Try Again in the banner. As a last resort, pkill -f -- 'Vibe Manager --terminal-host' stops the host and the agents it kept; their conversations are resumed at the next launch.
Full Disk Access is granted, and agents are still asked
Agents inherit the access of the process that started them. In Settings › Privacy, choose Restart When Idle or Restart Now….
The conversation stays empty
The conversation is read from the transcript the agent writes; a message appears once the CLI has written it. If a message you sent does not show within ten seconds, the view says so and offers the terminal, which always shows the truth.
The session's activity does not show (working, waiting…)
Turn on the agent's activity in Settings › Agents and approve its hooks.
An update is not offered
Vibe Manager › Check for Updates… says why when this copy cannot update itself. Release candidates are only offered on the Unstable channel. You can always download the latest disk image from GitHub Releases and drag it over the app.

More cases are covered in Help › Troubleshooting, which opens docs/operations.md.

What stays on your Mac

  • No account, no telemetry, nothing sent. The only network requests the app makes itself are the update check and the pages you, or your agents, open in the web view.
  • No credential is read. The agents use their own sign-in; Vibe Manager never sees an API key.
  • Conversations are read, not copied. The conversation view reads the agents' transcripts in memory; usage tracking only reads their counters.
  • Summaries, themes and avatars are generated by your agents, with your account, only when you turn them on or ask.
  • Every file of the app is readable by you alone.

The agents' own files — ~/.claude, ~/.codex — belong to them and are never modified.

Known limits

  • Restarting or logging out of the Mac stops the agents; Keep Running only outlives the app.
  • Each terminal keeps its last 5,000 lines.
  • A side terminal comes back as a new shell after a relaunch: what ran in it is not run again.
  • A store written by a newer version is refused by an older one: there is no downgrade.
  • The app is not sandboxed: an agent needs to run tools and read the folders it is given.

Uninstall

Quit the app — choose Stop All if it asks — then, in a terminal:

rm -rf "/Applications/Vibe Manager.app" \
  ~/Library/Application\ Support/com.hadrienl.VibeManager \
  ~/Library/Logs/Vibe\ Manager \
  "$TMPDIR/vibe-manager"
defaults delete eu.hadrien.VibeManager
tccutil reset All eu.hadrien.VibeManager
