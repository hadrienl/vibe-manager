Side terminals and web view

Each session has its own drawer of terminals for a server, a log or a git command, and its own web view that you and the agent both use.

Side terminals

View › Show Terminals (⌘J), or the terminal button of the status bar, opens a drawer under the session. View › New Terminal (⌘T) adds a tab; with the keyboard in the web view, ⌘T opens a web tab instead. Each tab is a login shell started in the session's folder, titled by the command it runs or the folder it is in.

The drawer of side terminals, under the session.
  • Hiding the drawer stops nothing. A hidden terminal that writes or ends is signalled on the status bar's button.
  • Double-click a tab to rename it; its context menu moves it left or right, or closes it (⌘W with the keyboard in it). ⌃⇥ and ⌃⇧⇥ cycle the tabs.
  • A shell that ended offers to restart or close.
  • Up to eight terminals per session.

The side terminals belong to their session: they stop when it closes, and come back when it reopens or when the app relaunches — same tabs, same order, same folder, what each showed — as new shells under a dated line. Nothing is run again. If you quit with Keep Running, they keep running with their agent.

Their history is the only terminal output written to disk; Settings › General turns it off and erases it.

The web view

View › Show Web View (⌥⌘B), or the globe in the toolbar, opens a browser beside the session, with its own tabs. Switching sessions switches tabs; nothing reloads.

The agent opened its local preview in the session's web view.
  • The Web menu has the usual commands: Open Location… (⌘L), Reload Page (⌘R), Back and Forward (⌘[ ⌘]), Open Page in Browser.
  • The address field also takes a ticket: type #142.
  • The session's ticket is its first tab, pinned. It is the one you gave the session, or the one its branch names (feat/142-… on GitHub or GitLab). The More menu sets, changes or removes it.
  • ⌘-click a link in a terminal opens it in the web view, or in your browser — Settings › Web View decides, and ⌥⌘-click does the other.
  • All sessions share one set of cookies, apart from Safari's: sign in to GitHub or GitLab once, and every ticket tab is signed in.

What the agent can do with it

Each agent is started with a tool server, vibe-browser, that gives it the session's web view: list, open, reload and close tabs, read a page's text or structure, take a screenshot, read the console, click, fill fields and run JavaScript. The agent sees its own session's tabs only. In the terminals, the vibe browser command does the same from a script, and an open https://… run by the agent shows the page here.

When the agent wants to act on another site, a banner in the web view asks: Deny, Allow Once, or Always Allow for that site. The agent waits two minutes at most; the session's row shows a hand meanwhile. The tab the agent opened carries a mark, the element it clicks is outlined, and the Agent Actions log lists what it did.

Reading is free everywhere, pages you are signed in to included: an agent can read a private ticket. Turn off Give agents the web view in Settings › Web View if you do not want that.
