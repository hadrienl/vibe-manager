Agents, restarts and quitting

Change agent or model without losing the work, put a closed session back to work, and quit without interrupting an agent in the middle of its turn.

Supported agents

Vibe Manager runs Claude Code and Codex CLI, each in its own terminal interface, with your account and your configuration. It passes no flag that lowers the permissions you set for your CLI, injects no API key, and reads no credential. What an agent may do inside a session is its own configuration: Vibe Manager neither widens nor narrows it.

Two additions are made at launch, for that launch only: the agent's hooks report its activity — working, waiting, finished — once you have approved them (Settings › Agents), and its tool server vibe-browser gives it the web view.

Switch agent or model

Session › Switch Agent… (⌃⌘M), or Switch… in the inspector's Agent section, changes the agent or the model of a session.

The new agent receives a summary you can read and edit first.
  • Another model of the same agent resumes the same conversation and sends nothing.
  • Another agent starts a new conversation, handed a summary of the session: who worked in it, where the work stands on each branch and worktree, its notes and the prompt it was created with. The summary is shown and editable before it is sent, and never presented as the conversation itself.

Nothing is stopped until you confirm with Stop and Switch (⌘Return). If the new agent fails to start, the session goes back to its previous agent, resumable as before. Every switch is kept in the session's history, and the conversation view keeps reading the transcripts of every agent the session had.

Restart a closed session

A closed session shows a bar: “This session is closed. Everything it carries is kept.” Restart — or Session › Restart Session, ⌃⌘R — puts it back to work with the same agent, model, folder and worktree.

A closed session keeps everything, and restarts in one command.
  • When the agent can resume its own conversation, it does, and is sent nothing.
  • When it cannot — no identifier was ever kept, or the CLI would refuse it — the app says so and offers a new process with a summary of the session, shown and editable before it is sent.

A session created with Add to To Do has never run: the same command reads Start Session.

Quit without stopping the agents

Every terminal runs in a terminal host, a background process with no window and no Dock icon. So when agents are working and you quit, Vibe Manager asks:

Keep Running
The agents carry on with their turn. At the next launch each one is back on screen as it was, nothing relaunched, nothing sent; one that finished meanwhile shows its last output. Side terminals keep running too.
Stop All
The agents are stopped, and left as the intention to resume them: at the next launch they come back with their CLI's own resume, without asking.

Tick Don't ask again, or choose in Settings › General, to always do the same. Updates use the same choice: an update can be installed while agents keep running.

Restarting or logging out of the Mac stops the agents: Keep Running outlives the app, not your macOS session. At the next launch, sessions are resumed natively.

After a crash

A crash is not an intention: at the next launch, a banner offers Resume Sessions or Ignore, instead of resuming them on its own. Sessions come back one at a time, with progress and a way to cancel; a restoration that would send a text to an agent is never automatic.
